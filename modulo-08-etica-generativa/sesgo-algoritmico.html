// el problema

El algoritmo no inventa el sesgo — lo aprende

Un modelo de aprendizaje supervisado (como los del Módulo 3) hace exactamente lo que le pediste: ajustar sus parámetros para reproducir las etiquetas de entrenamiento lo mejor posible. Si esas etiquetas vienen de decisiones humanas históricas que discriminaron sistemáticamente a un grupo, el modelo aprende a discriminar también — con la ventaja (para quien discrimina, la desventaja para todos los demás) de hacerlo a mayor escala y con una pátina de "objetividad matemática".

Este patrón ya ocurrió con sistemas reales: una herramienta interna de selección de personal que una empresa tuvo que abandonar porque penalizaba currículums que mencionaban actividades asociadas a mujeres, y un algoritmo de evaluación de riesgo de reincidencia usado en cortes de EE.UU. que sistemáticamente sobreestimaba el riesgo para acusados afroamericanos. Aquí vas a reproducir el mecanismo con datos sintéticos, para verlo de cerca.

// cómo funciona

Por qué quitar la variable protegida no alcanza

La primera reacción intuitiva es "quitemos el grupo como variable de entrada, así el modelo no puede discriminar por eso". Pruébalo con el botón 2 — la brecha entre grupos baja, pero está lejos de desaparecer. La razón: la experiencia medida está correlacionada con el grupo (aquí, a propósito, para simular variables proxy — señales que sin ser el atributo protegido directamente, lo predicen bastante bien). El modelo no necesita que le digas el grupo si puede inferirlo, parcialmente, de otras variables.

La reponderación (botón 3) ataca el problema desde los datos de entrenamiento: le da más peso a los ejemplos de grupos sub-representados en la etiqueta minoritaria, para que el modelo no aprenda a asociar "grupo B" con "rechazado" tan fuertemente. No es la única técnica de mitigación que existe, pero ilustra la idea general: corregir el sesgo requiere una intervención deliberada, nunca ocurre solo.

Dos nociones de "justo" que compiten: aquí medimos brecha de aprobación (¿se aprueba al mismo ritmo a ambos grupos?) y brecha en tasa de acierto (¿el modelo acierta igual de bien identificando candidatos realmente calificados en ambos grupos?). En general, un modelo no puede igualar ambas métricas a la vez si las tasas base de calificación difieren — elegir cuál priorizar es una decisión de valores, no solo de matemática.
// para discutir en clase

Preguntas para el debate

  • ¿Qué otras variables "proxy" del mundo real podrían filtrar información sobre género, raza o nivel socioeconómico sin mencionarlos directamente?
  • Si tuvieras que elegir entre reducir la brecha de aprobación o la brecha en tasa de acierto, y no puedes reducir ambas a la vez, ¿cómo decidirías cuál priorizar para un sistema de selección de personal?
  • ¿Quién debería ser responsable de auditar un sistema como este antes de ponerlo en producción — el equipo que lo construyó, un equipo independiente, un regulador externo?
  • Los casos reales mencionados arriba se descubrieron después de que las herramientas ya estaban en uso. ¿Qué señales de alerta, medidas desde el principio, podrían haberlos detectado antes?
